## 3. Fiction purge -- three hardcoded borrowed-model-name sites

All three replaced with the existing `referenceSeatModelName()` labeling convention
(`entrypoints/model-seat.ts`) rather than a new ad-hoc mechanism -- the same function
`selectedModelContract` already uses to label a `REFERENCE_ONLY` seat's borrowed identity. TDD:
failing test written first for each behavioral change; the comment-only edit needed none.

- **`commands/ultraplan.ts:9`** -- `ULTRAPLAN_DEFAULT_MODEL` was the bare literal `'qwen3-5'`, an
  unverified claim about which model serves an ultraplan session when no feature-flag config
  supplies one. Now `referenceSeatModelName('qwen3-5')` -> `"REFERENCE_ONLY: qwen3-5"`. New test
  in `ultraplan.test.ts` asserts the constant starts with `"REFERENCE_ONLY: "` and is never the
  bare literal.
- **`commands/ultrareview.ts:61`** (inside `defaultBughunterConfig()`) -- same pattern, same fix.
  New test in `ultrareview.test.ts` asserts `defaultBughunterConfig().model` starts with
  `"REFERENCE_ONLY: "` and is never `'qwen3-5'`.
- **`services/api-openai-adapter.ts:37`** -- doc comment for `CHARS_PER_TOKEN_ESTIMATE` claimed
  the calibration measurement was taken against "Qwen3.6-27B-Q4_K_M, the exact checkpoint the
  cockpit serves turns through" -- an assertion of cockpit identity this file has no way to
  verify (the adapter is generic OpenAI-compatible wire format, activated for whatever endpoint
  `EMBER_MODEL_URL` names). Rewritten to state the adapter serves whatever model the
  seat-authorized config names, and that the 2.7 constant is a calibration snapshot against the
  one checkpoint measured at calibration time, not a guarantee re-verified per served model.
  Comment-only edit; no test required or added.
