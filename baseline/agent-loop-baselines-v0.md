## Purpose

Codex, external coding agent B-class, Hermes/NemoClaw-class, ML research benchmark, and deterministic scripted/search surfaces are baseline comparators for Ember because local research progress depends on selecting the right experiment, using existing receipts, governing long jobs, parsing results, and preserving negative outcomes. Ember cannot claim a local research-operator advantage unless it beats or replaces these baselines under frozen, replayable tests.

## Baseline Objects

| Baseline | Current treatment | Required pin before Ember win |
|---|---|---|
| OpenAI Codex | Visible agentic coding and task-execution comparator for tool use, code modification, long-running task continuation, receipt-aware audit, and goal execution. | Official documentation snapshot, exact local Codex version/app build when testing, transcript/replay fixture, allowed tools, compute and wall-clock budget. |
| external coding agent B-class agent | Agentic coding and CLI comparator for repo navigation, edits, terminal execution, development-tool integration, and resident workflow continuation. | Official documentation snapshot or clean-room local behavior fixture, exact tested version where available, transcript/replay fixture, legal provenance boundary. |

| ML research benchmarks | MLE-bench, MLAgentBench, AI Scientist v2, and Kosmos-class scientific-discovery anchors constrain task selection, no-recompute choices, negative-result handling, and overclaim prevention. | Selected fixture, no-recompute reason or local replay command, scoring rubric, and compute-spend packet where needed. |
| Non-agent scripted/search baseline | Deterministic baseline for tasks that do not require language-agent behavior. | Script, seed, search space, budget, and receipt parser. |

## Required Frozen Artifacts

- task manifest and expected outcome;
- allowed tool list and denied tool list;
- cache/receipt inventory available before run;
- wall-clock, CPU, GPU, network, and token budget;
- compute-spend packet for long jobs;
- no-recompute decision log;
- transcript schema and score schema;
- replay command;
- failure taxonomy;
- human-intervention ledger.

## Required Metrics

- research-operation task success;
- correctness of next-experiment selection;
- quality of no-recompute decision;
- wall-clock and GPU/CPU/network budget consumed;
- number of valid tool calls and invalid/repeated calls;
- receipt parser correctness;
- negative-result preservation;
- ability to preserve goal constraints across compaction, crash, resume, or handoff;
- code-change quality under deterministic tests when code edits are part of the task;
- human-intervention count and scope.

## Anti-Cheat Gates

- no Ember win unless baselines receive the same files, tools, budgets, task statement, and cached receipts;
- no counting private model capability rumors as measured comparator facts;
- no using private source expression from comparator tools inside Ember implementation;
- no treating C5 self-improvement receipts as local-agentic research success unless the research-operation suite itself is frozen and passed;
- no hosted paid judge as required authority when the same rubric can be applied locally;
- no success if the verifier cannot replay receipt parsing.
