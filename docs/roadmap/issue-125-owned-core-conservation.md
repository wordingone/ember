# Issue #125 current-scale conservation ruling

Status: `SUPERSEDED_NOT_PLANNED`

Issue #125's original execution vehicle is obsolete. Its premise described a
roughly 244K-parameter owned core that needed widening beyond one million
parameters for the historical C14/rung-2 program. The issue's own 2026-07-05
correction established that this was a stale reading: the core was already on
the order of 100M parameters, while 264,192 described only its LoRA trainable
surface. PR #132 landed CPU-preparation around the corrected rank-expansion
idea, but no closure-grade GPU run or D7 dual-layer receipt followed.

Current Ember has a clean-genesis 3B floor and EMBER-05 owns verified expert
accretion. Recreating the historical sub-3B C14/rung-2 vehicle would violate
that trajectory and would not supply current model evidence. This ruling
therefore retires only that vehicle and the incorrect 244K-total-core premise;
it does not convert the unfinished GPU half into completion credit.

## Lossless transfer

Canonical EMBER-05 issue #1119 accepted the surviving obligations at
https://github.com/wordingone/ember/issues/1119#issuecomment-5221099563:

1. A current trainable-surface expansion must exceed its preregistered floor
   with margin and pass both run-start and receipt-semantic gates.
2. Primary growth must prove function preservation on a pinned owned-corpus
   batch and bind exact parent/child identity, operator configuration,
   before/after counts, and `no_borrowed_weights=true`.
3. Repeated preservation failure may fall back to from-scratch re-derivation
   only with explicit `lineage: re-derived` disclosure.
4. Stabilization must use a governed current-3B-compatible launch and preserve
   its loss trace.
5. The realized model must load and complete a bounded resident smoke episode;
   this is plumbing evidence, not a scored capability claim.
6. Negative evidence, deletion tests, rollback, and lineage conservation remain
   mandatory.

## Authority and claim boundary

The sole current authority is Ember Lab together with the governed runner,
checkpoint/corpus custody, and EMBER-05/#1119. No historical cbase, 2.2B,
C14, or parallel launch/receipt authority is revived. This documentation
records an obligation transfer only: it proves no GPU execution, stabilization,
training sufficiency, checkpoint availability, capability, benchmark result,
or EMBER-05 completion. Missing current-scale evidence keeps #1119 open and
reopens the corresponding EMBER-05 certificate clause.
