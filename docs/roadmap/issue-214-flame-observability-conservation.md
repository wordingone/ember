# Issue #214 flame-observability conservation

Status: `SUPERSEDED_NOT_PLANNED`

## Ruling

Issue #214's historical flame and observatory carrier is superseded by the
current EMBER-03 operator-surface program. Only that historical carrier is
retired. Its flame-truth, live-learning-state, and terminal-acceptance
obligations remain current and are conserved below without crediting any
implementation or live acceptance that has not occurred.

## Lossless current-owner transfer

Canonical owner: [EMBER-03/#1117](https://github.com/wordingone/ember/issues/1117).

Accepted transfer: https://github.com/wordingone/ember/issues/1117#issuecomment-5224505096

The accepted transfer preserves every still-valid obligation from #214 and its
specification comments 4892001242 and 4994155298.

### Flame truth

1. Every visible flame parameter is a pure, documented function of named,
   machine-readable current state with an explicit staleness bound. The current
   equivalents of goal status, goal transition/continuation events, totality
   evidence, owned-serving liveness, budget state, receipt activity, governed
   accelerator use, and ledger transitions must bind intensity, motion, color
   temperature, flicker, size, sparks, smoke, ember-bed, and crown behavior.
   An unbound parameter is a defect.
2. Idle and missing-data states are honest: zero activity becomes a small,
   nearly still pilot ember; stale or absent feeds decay within the bound to a
   visibly labeled no-state condition. Last-known-good looping and synthetic
   liveliness are forbidden.
3. Run start, receipt arrival, goal continuation/transition, blocked state,
   budget pressure, board incident, and serving outage have distinct,
   operator-legible responses. Decorative dither is permitted only when its
   amplitude is bounded by real signal magnitude and cannot resemble activity
   at zero.
4. The binding table is checked in as code and documentation. Closed tests must
   cover all-null state, each named event class, deterministic parameter
   vectors, feed death/staleness, and the no-source-less-animation rule.
5. The decorative state-blind flame is retained only as the named historical
   failure baseline; it is not a current truth source or acceptance artifact.

### Live stacked learning-state graphs

6. At the operator's real half-screen viewport, the current Ember CLI provides
   a responsive, collapsible right-side stacked-graph surface without covering
   the transcript or input. It shows: loss by step/checkpoint; throughput and
   efficiency (`tok/s`, `tok/GPU-joule`, MFU, with missing power disclosed);
   owned-growth counts and promotion/deletion events; and frozen capability
   vectors for text, image, audio, reasoning, and structured tools.
7. Every plotted point binds exact current commit, checkpoint manifest,
   governed run/energy receipt, evaluator receipt, and timestamp. Missing data
   renders as an explicit gap or `NOT MEASURED`, never zero. Preflight and
   otherwise non-admissible evidence remain visibly distinct from measured or
   capability-bearing results.
8. Target-crossing wall time, active FLOPs, and GPU joules are plotted
   separately. Utilization and raw throughput remain diagnostics and cannot
   substitute for target crossing. Vision, energy, and evaluation evidence
   must come from the same governed run where the registered comparison
   requires it.

### Terminal acceptance and evidence law

9. Acceptance runs the compiled current-public Ember CLI through
   idle -> run-start -> receipt -> blocked -> idle, plus one receipt arrival,
   one missing-sample gap, one checkpoint-growth event, and one frozen-evaluator
   result. It captures source/executable/state/receipt-bound frames for every
   transition, a scripted resize, and the operator's actual half-screen
   viewport.
10. The experience leg compares the current surface side-by-side with the
    named decorative failure baseline and the field exemplar, with a written
    wince list. A stranger must be able to distinguish progress, efficiency,
    growth, capability, idle, blocked, stale, and outage states without opening
    files.
11. Malformed, stale, foreign-run, replayed-as-live, deleted, or interrupted
    evidence fails closed and remains reconstructable. Rollback and negative
    evidence are retained. No flame or graph pixel grants training,
    checkpoint, capability, sufficient-pretraining, energy, target-crossing,
    or milestone credit beyond its exact bound receipts.

## Architecture and claim boundary

The current Ember Lab control plane and the existing Ember CLI
telemetry/journal/custody surfaces remain the sole authorities. This ruling
creates no second dashboard, renderer, telemetry feed, receipt family,
launcher, model, or policy authority.

`NO_NEW_PARALLEL_AUTHORITY`

Historical endpoint names, keyframed implementations, predicted dates, and
issue-local sequencing are provenance only. Qualifying compiled live
acceptance has not already been demonstrated. No live run, training,
checkpoint, capability, sufficient-pretraining, energy, target-crossing, or
milestone-completion claim is made.
