# Contributing to Ember

Start from exact public source and identify the owning domain before editing. Use the
[documentation map](domains/governance/DOCS-README.md) and [system overview](architecture/system-overview.md) to find
the canonical surface. If two current pages claim the same concept, consolidate or record an
explicit supersession instead of creating a third owner.

<a id="ember.claim.contribution-evidence"></a>
Every change must separate what was designed, implemented, executed, measured, independently
reviewed, and admitted. Run the commands documented for the changed path at the exact reviewed
head. Preserve receipts and negative evidence; prose cannot upgrade a claim. The
[reproducibility charter](domains/governance/charter/REPRODUCIBILITY.md) defines the public evidence boundary, and the
[verification guide](guides/VERIFY.md) provides the smallest safe checks.

Do not place mutable run, issue, checkpoint, or receipt status in the README. Update the canonical
authority or evidence owner and link to it. Documentation additions that are current or normative
entry pages require unique metadata IDs and a generated-index update.
